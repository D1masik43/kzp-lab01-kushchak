# Спортивна ліга — консольний звіт

Лабораторні роботи № 1–4 з курсу «Кросплатформні засоби програмування».
Варіант 17.

## Призначення

Програма читає записи результатів матчів з `data/input.csv`, перевіряє їх,
обчислює показники ліги та формує звіт у консоль і текстовий файл.

## Формат входу

Один запис розміщують у рядку, поля розділяють крапкою з комою (`;`).
Файл кодують у UTF-8. Формат запису:

```
home;away;homeScore;awayScore;attendance
```

| Поле        | Тип    | Опис                          |
|-------------|--------|-------------------------------|
| home        | String | назва команди господарів      |
| away        | String | назва команди гостей          |
| homeScore   | int    | голи господарів                |
| awayScore   | int    | голи гостей                    |
| attendance  | int    | кількість глядачів на матчі    |

Приклад:

```
Динамо;Шахтар;2;1;18500
```

## Показники звіту

1. Кількість коректних записів.
2. Середня кількість голів за матч.
3. Найбільша відвідуваність.
4. Сумарна відвідуваність.

## Структура класів (лабораторна робота № 2)

Один рядок CSV перетворюється на об'єкт класу-сутності з приватними полями й
перевіркою інваріантів у конструкторі. Геттери (`getHomeTeam`, `getAwayTeam`,
`getHomeScore`, `getAwayScore`, `getAttendance`) і `toString()` з
форматуванням через `Locale.ROOT`.

Підсумкові показники звіту зберігаються в незмінному `record ScoreAttendance`
(`validCount`, `averageGoals`, `maxAttendance`, `totalAttendance`) із власною
перевіркою допустимості значень у компактному конструкторі.

`LeagueProcessor.process(List<String> lines)` розбирає рядки на список
об'єктів спільного типу, а підсумок обчислює окремим методом
`summarize(List<Match>)`. Зовнішній формат звіту й показники не змінились
порівняно з лабораторною роботою № 1.

## Ієрархія типів (лабораторна робота № 3)

Клас-сутність з лаб. 2 розділено на спільний абстрактний базовий тип і два
підтипи з різною поведінкою — нічия в лізі допустима, а в плей-офф ні:

- `Match` (`abstract`) — спільні поля (`homeTeam`, `awayTeam`, `homeScore`,
  `awayScore`, `attendance`), перевірка спільних інваріантів у конструкторі,
  `equals`/`hashCode` за підтипом (`getClass()`) і значеннями полів,
  абстрактні методи `getKind()`, `homePoints()`, `awayPoints()`.
- `LeagueMatch extends Match` — матч регулярного сезону; нічия дозволена;
  очки нараховуються за схемою «перемога 3 – нічия 1 – поразка 0»;
  `LeagueMatch.fromCsv(String line)` — єдине джерело об'єктів для
  `data/input.csv`, тому консольний і файловий звіт лишились незмінними.
- `PlayoffMatch extends Match` — матч плей-офф; власний інваріант відхиляє
  нічию (`IllegalArgumentException`); переможець отримує 2 очки, переможений — 0.
- `MatchKind` (`enum`: `LEAGUE`, `PLAYOFF`) — категорія матчу, повертається
  через `getKind()`, порівнюється через `==`.

Жодне місце коду не перевіряє конкретний підтип через `if`/`switch`: і
звичайний звіт (`LeagueProcessor.summarize`), і нарахування очок працюють
через спільний тип `Match`, викликаючи `homePoints()`/`awayPoints()`
поліморфно.

## Потокова обробка (лабораторна робота № 4)

Основний конвеєр (`data/input.csv` → `LeagueProcessor` → консольний звіт)
лишився незмінним — методика лаб. 4 вимагає зберегти вхідні дані й зовнішній
формат звіту лаб. 1-3. Його внутрішній підсумок (`LeagueProcessor.summarize`)
переписано з циклу на Stream API (`mapToInt`/`mapToLong`/`max`), результат
той самий.

Для п'яти Stream-запитів варіанта 17, яким потрібні поля «тур» і «дата»
(яких немає в `data/input.csv`), додано окрему сутність-композицію
`ScheduledMatch` (матч + тур + дата) і окремий контрольний набір
`data/schedule.csv` у форматі:

```
home;away;homeScore;awayScore;attendance;tour;date
```

`LeagueScheduleQueries` (`src/main/java/ua/lpnu/kzp/LeagueScheduleQueries.java`)
реалізує п'ять іменованих запитів над `List<ScheduledMatch>`:

1. `matchesOfTour` — `filter` за номером туру.
2. `scoresAsText` — `map` рахунку в текст `"H:A"`.
3. `countByTour` — `Collectors.groupingBy` + `Collectors.counting()`, ключі
   впорядковані зростанням туру (`TreeMap`).
4. `homeGoalsStatistics` — `Collectors.summarizingInt` голів господарів.
5. `topByGoalDifference` — складений компаратор (різниця голів спаданням,
   дата зростанням) + `sorted().limit(N)`; `N < 0` відхиляється
   `IllegalArgumentException`, `N = 0` повертає порожній список, `N` більший
   за розмір колекції — весь список.

Окремий метод `findByTeams` повертає `Optional<ScheduledMatch>` для пошуку за
парою команд; за дубльованого ключа — перший запис у вхідному порядку.
Жоден запит не перевіряє конкретний підтип `Match` через `if`/`switch` і не
змінює вхідну колекцію.

## Збірка та запуск

```text
mvnw.cmd verify
mvnw.cmd package
java -jar target/lab01-1.0.0.jar
```

На macOS та Ubuntu замість `mvnw.cmd` використовуйте `./mvnw`.

### Аргументи командного рядка

```text
java -jar target/lab01-1.0.0.jar [--help] [--version] [--input <файл>] [--output <файл>]
```

- `--help` — вивести довідку та завершити роботу;
- `--version` — вивести версію програми;
- `--input <файл>` — шлях до вхідного CSV (типово `data/input.csv`);
- `--output <файл>` — шлях до файла звіту (типово `out/report.txt`).
