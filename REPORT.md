# Звіт до лабораторної роботи № 1

## 1. Тема, номер і варіант

- Тема: розгортання Java-проєкту та базова обробка даних.
- Предметна область: варіант 17 — «Спортивна ліга».
- Операційна система: Linux (Debian 13), Java 21, Maven 3.9.9.

## 2. Мета роботи

Пройти повний шлях від створення репозиторію й налаштування інфраструктури до
версії простої консольної програми, яку можна відтворено зібрати й запустити на
Windows, macOS та Ubuntu.

## 3. Постановка задачі

Формат одного запису: `home:String; away:String; homeScore:int; awayScore:int; attendance:int`.

Показники варіанта:

1. Кількість коректних записів.
2. Середня кількість голів за матч (`homeScore + awayScore`, усереднено за коректними записами).
3. Найбільша відвідуваність (`attendance`).
4. Сумарна відвідуваність.

## 4. Структура програми

```
src/main/java/ua/lpnu/kzp/
├── Main.java             — точка входу, розбір аргументів командного рядка, оркестрація
├── LeagueProcessor.java  — розбір, перевірка записів і обчислення показників (бізнес-логіка)
└── FileReport.java       — кросплатформне читання/запис текстових файлів UTF-8
src/test/java/ua/lpnu/kzp/
└── LeagueProcessorTest.java — модульні тести бізнес-логіки
data/input.csv            — приклад вхідних даних (5 коректних, 5 хибних рядків)
```

Потік даних: `Main` читає рядки через `FileReport.readLines` → передає їх у
`LeagueProcessor.process` (розбір і перевірка кожного рядка, накопичення показників
і списку помилок) → `LeagueProcessor.formatReport` формує текст звіту → `Main`
виводить той самий текст у консоль і записує через `FileReport.writeReport`.
Логіка обчислення не дубльована між двома приймачами виводу.

## 5. Інфраструктура

- Maven-проєкт описано в `pom.xml`: координати `ua.lpnu.kzp:lab01:1.0.0`,
  `maven.compiler.release=21`, кодування UTF-8.
- Залежність JUnit 5 (`5.12.2`) підключена зі `scope=test`, бібліотеку не копійовано
  до репозиторію.
- Статичний аналізатор SpotBugs (`4.9.7.0`) запускається у фазі `verify`.
- `maven-shade-plugin` (`3.6.0`) формує виконуваний jar із залежностями
  (`target/lab01-1.0.0.jar`) з головним класом `ua.lpnu.kzp.Main` і записує версію
  проєкту в маніфест (`Implementation-Version`), яку читає `--version`.
- Maven Wrapper (`mvnw` / `mvnw.cmd`, Maven 3.9.9) дає змогу зібрати проєкт без
  локальної установки Maven.
- `.github/workflows/ci.yml` запускає `verify` на матриці `ubuntu-latest`,
  `windows-latest`, `macos-latest` і публікує зібраний jar як артефакт workflow.

## 11. Відповіді на контрольні питання

1. `pom.xml` описує координати проєкту (groupId, artifactId, version), версію
   Java, кодування, залежності та плагіни збірки — Maven не вгадує ці
   властивості з назв каталогів.
2. `test` компілює й запускає тести; `verify` додатково запускає статичний
   аналізатор (SpotBugs); `package` додатково формує jar у `target/`. Кожна
   наступна фаза виконує всі попередні.
3. Maven Wrapper (`mvnw`/`mvnw.cmd`) дає змогу зібрати проєкт без попередньо
   встановленого Maven потрібної версії — Wrapper сам завантажує її при
   першому запуску, лишається потрібною лише JDK.
4. Метод `main(String[] args)` — точка входу JVM у програму; отримує аргументи
   командного рядка й запускає оркестрацію читання, обробки та виводу звіту.
5. Примітивний тип (`int`, `double`, ...) зберігає значення безпосередньо і має
   фіксований набір операцій мовою; `String` — посилальний тип, об'єкт з
   методами (наприклад, `split`, `isBlank`), а змінна зберігає посилання на
   нього.
6. Якщо ділити `int` на `int`, результат — цілочислове ділення з відкиданням
   дробової частини; явне приведення одного з операндів до `double` (наприклад,
   `(double) total / count`) зберігає дробову частину.
7. `Integer.parseInt("abc")` кидає `NumberFormatException`; у програмі це
   перехоплено в `LeagueProcessor.process`, рядок додається до списку помилок
   з номером і причиною, обробка інших рядків продовжується.
8. Мовчазний пропуск помилкового рядка приховує проблему в даних і робить звіт
   недостовірним без пояснення; методичка прямо вимагає повідомляти номер
   рядка та причину пропуску.
9. `String.split(";", -1)` з другим аргументом `-1` зберігає порожні кінцеві
   поля (наприклад, порожнє останнє поле не відкидається), тому кількість
   елементів масиву точно відповідає кількості полів запису.
10. `Path.of(...)` сам обирає роздільник шляху, коректний для поточної ОС;
    жорстко закодований `"data\\input.csv"` працює лише на Windows і ламається
    на macOS/Ubuntu.
11. `StandardCharsets.UTF_8` задає кодування явно, незалежно від локалі
    операційної системи, тому український текст читається й пишеться однаково
    на Windows, macOS та Ubuntu.
12. `%n` вставляє роздільник рядка, прийнятний для поточної операційної
    системи (`\r\n` на Windows, `\n` на Unix); `\n` завжди вставляє символ
    переведення рядка Unix, що на Windows дає невідповідний файлу формат.
13. У варіанті 17 перевіряють: кількість полів (рівно 5), непорожні назви
    команд (`home`, `away`), коректність цілих чисел (`homeScore`, `awayScore`,
    `attendance`) і їх невід'ємність, а також порожній рядок.
14. Тести `averageIsZeroWhenNoValidRecords` (середнє = 0.0 без коректних
    записів) і `formatReportProducesFixedDecimalPlaces` (перевірка `%.2f`)
    виявлять помилку в обчисленні середнього, зокрема цілочислове ділення без
    приведення до `double`.
15. Статичний аналізатор (SpotBugs) шукає потенційні дефекти в скомпільованому
    байт-коді (витік внутрішнього стану, ресурси, що не закриваються, тощо),
    доповнюючи компіляцію й тести перевіркою якості коду.
16. GitHub Actions автоматично запускає збірку й перевірки для кожної зміни
    (push, pull request) на кількох операційних системах, підтверджуючи
    кросплатформність незалежно від локального середовища розробника.
17. GitHub Issue на дефект має містити кроки відтворення, очікуваний і
    фактичний результат (форма `.github/ISSUE_TEMPLATE/bug.yml`).
18. У розділі про академічну доброчесність потрібно вказати назву й версію
    інструмента ШІ (або що він не використовувався), ролі-агенти, промпти,
    прийняті рекомендації, виправлені помилки та підтвердження розуміння
    всього поданого коду.
19. Агент DevOps консультує щодо Maven, статичного аналізатора, пакування й
    GitHub Actions; агент Валідатор складає перелік крайових випадків і формує
    дефекти за результатами перевірки, не змінюючи код.
20. Найскладніше пояснити рядок
    `double averageGoals = validCount == 0 ? 0.0 : (double) totalGoals / validCount;`
    — потрібно одночасно розуміти цілочислове накопичення `totalGoals`,
    необхідність явного приведення до `double` для збереження дробової
    частини й обробку випадку поділу на нуль при відсутності коректних
    записів.
